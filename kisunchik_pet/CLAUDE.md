# CLAUDE.md - инструкции для ИИ-агентов по проекту kisunchik_pet

Настольный питомец Кисунчик: прозрачное окно поверх рабочего стола Windows,
спрайтовая анимация, клики по зонам тела, сам гуляет по всем мониторам,
учит английскому (карточка + озвучка, прогресс обучения по блокам).

Действуют общие правила репозитория `../CLAUDE.md` и `../AGENTS.md`:
по-русски, без pip без явной просьбы, комментарии без эмодзи и спецсимволов
(только обычный дефис `-`), после изменений - прогонять тесты.

## Как устроен проект

Код в стиле ООП, как в главном проекте `english_for_programmers_gui`:

- `core/` - логика без окон, всё тестируется без экрана:
  `SpriteAtlas`, `EnglishTutor` + датакласс `Word`, `Speaker`,
  `BubbleImage`, `BehaviorPolicy`, датакласс `Settings`
  (JSON рядом с программой), модуль `autostart`,
  `ProgressStore` (дневник обучения, `progress.json`).
- `gui/` - экран и окна: `VirtualScreen` + датакласс `ScreenArea`,
  `LayeredRenderer` (Win32 UpdateLayeredWindow), `PetWindow` (tkinter),
  `KisunchikApp` (главный цикл, связывает всё через внедрение зависимостей),
  `ProgressWindow` (табло прогресса с графиками).
- `run.py` - тонкая точка входа: DPI-awareness, потом `KisunchikApp.run()`.
- `tools/make_icon.py` - собирает `assets/icon.ico` из мордочки котика;
  exe пересобирается с ключом `--icon assets/icon.ico`.

## Три подводных камня (уже обожглись, не ломать)

1. **ctypes без прототипов режет 64-битные дескрипторы до int**, и
   UpdateLayeredWindow молча не рисует. В `gui/renderer.py` у всех
   user32/gdi32-функций обязаны стоять argtypes и restype.
2. **Структуры POINT/SIZE/BLENDFUNCTION объявляются ДО argtypes**,
   иначе NameError при импорте.
3. **Tk создаёт два окна**: рисовать надо в видимое - его ищем по
   заголовку `KisunchikPet` среди окон своего процесса
   (`find_own_window` в `gui/window.py`).

Ещё: позицию окна двигаем через `SetWindowPos`, не через `root.geometry` -
Tk сам пересчитывает координаты и сдвигает окно, где ему вздумается.
Цвета для UpdateLayeredWindow - BGRA с premultiplied alpha (уже в renderer).

## Что уже ломалось и исправлено (не повторять)

Эти баги нашлись ревью 21.11.2026, все исправлены. Если агент их
воспроизведёт — он не читал этот раздел.

1. **`find_own_window` без argtypes/restype** — `GetWindowThreadProcessId`,
   `IsWindowVisible`, `GetWindowTextLengthW`, `GetWindowTextW` должны быть
   с прототипами, иначе ctypes режет 64-битные HWND до c_int.

2. **`winfo_id` как фолбэк** — если `find_own_window` вернула None, нельзя
   подставлять `root.winfo_id()`: это внутреннее окно Tk, рисунок уйдёт в
   него, и котик молча невидим. Надо упасть с RuntimeError.

3. **`GetTickCount` без restype** — DWORD без restype превращается в знаковый
   c_int, и через ~25 дней аптайма детектор бездействия ломается (idle < 0).

4. **`SetProcessDpiAwareness` не проверяет HRESULT** — функция возвращает
   HRESULT значением, а не бросает исключение. Без проверки фолбэк
   `SetProcessDPIAware()` никогда не вызовется при E_ACCESSDENIED.

5. **`progress.json` пишется неатомарно** — сбой посреди `write_text` =
   битый файл = полная потеря дневника. Писать в `.tmp` и `os.replace()`.

6. **Утечки: `bind_all`, шрифт в about_window, IntVar в меню, подменю** —
   `bind_all("<MouseWheel>")` не снимается, шрифт в `<Enter>` создаётся
   заново, `IntVar` и вложенные меню не уничтожаются при перестройке.

7. **`show_word` без проверки на None** — `tutor.next_word()` может
   вернуть None (словарь пуст или все блоки выключены); дальше `word.category`
   падает с AttributeError.

8. **Гонка в `Speaker.restart()`** — старый поток-зомби делит очередь с новым,
   его `finally` перезаписывает `ready`. Каждое поколение диктора получает
   свою очередь, `finally` не трогает `ready` чужого поколения.

9. **Офлайн-фолбэк пропускает не-OSError** — `IncompleteRead` не ловится
   `except OSError`. Ловить `except Exception`.

10. **«Залипшая» ошибка синтеза** — после офлайн-фолбэка `speech_error`
    не очищалась на успешном произношении. Очищать при любом успехе.

11. **`tutor._pick` падает при весе ≤ 0** — `random.choices` бросает
    ValueError. Клампить вес в `max(0.0, float(w))` при загрузке, и если
    сумма весов = 0 — давать равные шансы.

12. **`settings.json` не-словарь = краш** — `data.items()` при массиве/строке
    даёт AttributeError. Проверять `isinstance(data, dict)`.

13. **Генераторы не идемпотентны** — `build_categories.py` затирает блоки
    `abc_*` от `build_basics.py`. Сохранять существующие `abc_*` при записи.

## Процессор и журнал

Окно перерисовывается, только если изменилась подпись кадра (состояние,
кадр, позиция, размер, пузырь) - `tick()` в `gui/app.py`. Без этого было
33 перерисовки в секунду на месте, это 8-9% ядра. Не возвращать
безусловный push.

`pet.log` рядом с exe - общий журнал затей и ошибок: клики, прогулки,
сон, состояние диктора, автозапуск, traceback из главного цикла.
Первое средство диагностики "котик чего-то не делает".

## Kaspersky: почему котик запускается через pythonw, а не exe

На машине стоит Kaspersky Anti-Virus. Свежесобранный неподписанный exe
он сажает в ограниченную группу, и тому запрещено:
- писать автозапуск в реестр (WinError 5, и запись, созданная снаружи,
  Kaspersky откатывает);
- распаковывать onefile во временную папку ("Could not create
  temporary directory!");
- пользоваться голосами SAPI: и дочерний PowerShell (Speak висит
  молча), и прямой вызов SpVoice из exe (`Speak: 0x8004503a` -
  голос "не найден"). Тот же код из-под python.exe говорит свободно.

Поэтому боевой запуск - `pythonw run.py` (ярлык и автозапуск ведут
на него), а exe - только после добавления в доверенные приложения
Kaspersky, и собирать строго `--onedir`.

Озвучка: `core/speech.py` (ENGINE="hybrid-2") - два движка.
Офлайн: SAPI SpVoice прямо в процессе (ctypes, COM, vtable Speak -
слот 20), без дочерних процессов; английский голос выбирается SSML
`<voice required="Language=409">`, характеры (медленно/быстро/ниже/
выше) - через `<rate>` и `<pitch>`. Онлайн: Google Translate TTS
(без ключа, домен задаёт акцент), mp3 играется через winmm MCI;
при ошибке сети - автоматический фолбэк на офлайн с записью причины
в `speech_error`. Выбор голоса - настройка `voice` (`sapi:auto`,
`sapi:slow`, ..., `gtts:co.uk`, ...), меню строится из
`voice_choices()`. Счётчик `said_count` растёт после каждой
произнесённой фразы - по нему в pet.log видно, что речь звучала.

Блоки слов: `assets/categories.json` (18 блоков, покрытие 4070/4070)
собирается `tools/build_categories.py` из `english_for_programmers_gui/data/*.txt`
(строка `# topic:` - русское название). Репетитор фильтрует слова
по настройке `categories` (None - все; пустой фильтр безопасно
откатывается на все слова). Меню "Что учить" в `gui/app.py`
(`_apply_category_choice`) хранит None, когда включены все блоки.

## Автозапуск и антивирус

Автозапуск меняется галочкой в меню (настройка `autostart`).
`core/autostart.py` пробует по цепочке: реестр напрямую, reg.exe,
ярлык в папке "Автозагрузка". Антивирус на машине пользователя запрещает
свежесобранному exe всё три (WinError 5 / UnauthorizedAccess), при этом
те же записи из обычной командной строки проходят. Поэтому после
переключения приложение проверяет факт (`is_enabled`) и при расхождении
честно откатывает галочку и показывает пузырь с пояснением - не убирать
эту проверку, иначе меню будет врать.

## Мультимонитор

Границы считаем по виртуальному экрану (`gui/screen.py`), а не по главному
монитору. Левый/верхний мониторы могут иметь отрицательные координаты -
это нормально, `ScreenArea.clamp` это учитывает. Не заменять на
`GetSystemMetrics(0/1)` - это снова запрёт котика на одном мониторе.

**Котик не должен уползать за край.** Цель прогулки (`walk_target`)
хранится в координатах КОТИКА, а не окна: окно с пузырём шире котика
и сдвинуто влево, и раньше появление пузыря посреди прогулки выталкивало
котика за правый край. Плюс в каждом кадре работает страховка
`_keep_on_screen()` в `gui/app.py`: окно поджимается к виртуальному
экрану, котик - к своему монитору (котик важнее пузыря). Регрессия
покрыта `tests/test_onscreen.py` - не выносить.

## Пузырь со словом

Главный принцип `core/bubble.py`: шрифт НИКОГДА не уменьшается,
растёт сам пузырь - сначала в ширину (min_width..max_width), потом
в высоту переносами строк (слишком длинное слово режется посимвольно).
Пожалуйста, не возвращать `_fit_font` в `render`: мелкий текст
нечитаем, пользователь это заметил и попросил так больше не делать.

## Обучение: блоки, дневник, табло

- Словарь = 4070 слов тренажёра + азбука (алфавит 26, цифры 29,
  первые слова 60) = 4110. Блоки: 21 (группы basics/topics/speech/style).
- Порядок сборки словаря с нуля: `tools/build_categories.py` (из
  тренажёра), затем `tools/build_basics.py` (азбука). basics переносит
  уже существующие слова (hello, one...) в блоки азбуки и обновляет
  им перевод на точный с синонимами через запятую - дублей слов нет,
  проверяется тестом.
- `core/progress.py` (ProgressStore, `progress.json` рядом с программой):
  по каждому блоку перемешанный порядок слов и закладка, по каждому
  слову счётчики показов/произношений, по дням - активность для графика.
  Сохранение только при изменениях (`_dirty`) и принудительно на выходе.
- Репетитор с дневником работает как учебник: новые слова - по закладке
  из самого отстающего включённого блока, треть показов - повторение
  виденных (редко виденные чаще). Без дневника - старый взвешенный
  случайный режим (так работают тесты).
- `gui/progress_window.py` - табло прогресса. Правило вёрстки: все
  отступы и высоты считаются от `tkfont.metrics`, список блоков -
  обычные виджеты в grid, окно само себе ставит minsize по содержимому.
  Экран пользователя 200% - захардкоженные пиксели дали наложение
  строк, это был болезненный баг, не возвращать. График недели
  перерисовывается по `<Configure>` при растягивании окна.

## Тесты

```text
python -m unittest discover -s tests -t .
```

`tests/test_live_screen.py` поднимает настоящее окно и проверяет его
снимком экрана - не выносить из прогона, это главная защита от
"окно есть, а котика не видно". `tests/test_onscreen.py` - котик
не уползает за край. `tests/test_progress_window.py` - вёрстка
табло без наложений.

  не коммитить.
