# Тесты English for Programmers

Тесты нужны, чтобы изменения в программе не ломали незаметно то, что уже работает.
Используется `unittest` из стандартной библиотеки Python, ничего устанавливать не нужно.
Все команды выполняются из папки `english_for_programmers_gui/`.

## Как устроены папки

| Папка | Что проверяет | Сколько идёт | Когда запускать |
| --- | --- | --- | --- |
| `unit/` | логику без окон: слово, проверку ответа, занятие, прогресс, настройки, словарь, расчёт окна, подготовку текста для голоса | доли секунды | после каждого маленького изменения |
| `gui/` | настоящее окно: страницы, горячие клавиши в русской раскладке, сохранение и продолжение занятия | около 1,5 минуты | перед коммитом |
| `system/` | программу целиком: запуск `main.py` отдельным процессом, сборку exe, настоящий звук | от 10 секунд до 2 минут | перед коммитом и после сборки exe |
| `manual/` | ничего не проверяет сама: это сценарии, чтобы посмотреть и послушать | - | по желанию |

`support.py` - общие помощники (временный словарь, нажатие клавиши, функции Windows),
`gui/base.py` - основа для тестов окна.

## Запуск

Быстрые тесты логики:

```text
python -m unittest discover -s tests/unit -t .
```

Все тесты (звук и сборка exe пропускаются):

```text
python -m unittest discover -s tests -t .
```

Нормальный результат: `OK (skipped=12)`. Пропущено 12 необязательных тестов: 7 со звуком
и 5 со сборкой exe.

Один файл или один тест:

```text
python -m unittest tests.unit.test_lesson -v
python -m unittest tests.unit.test_lesson.RetryMistakesTests.test_no_retry_without_mistakes
```

Флаг `-v` печатает имя каждого теста. Имена написаны как требования к программе, поэтому
такой список читается как описание того, что программа умеет.

### Звук и сборка exe

Эти тесты медленные: для звука нужны интернет и колонки, для сборки нужен PyInstaller.
Поэтому они включаются переменными окружения. В PowerShell:

```powershell
$env:EFP_AUDIO_TESTS = "1"
$env:EFP_BUILD_TESTS = "1"
python -m unittest discover -s tests/system -t . -v
Remove-Item Env:EFP_AUDIO_TESTS
Remove-Item Env:EFP_BUILD_TESTS
```

Во время проверки звука будут слышны английские фразы. Сборка идёт во временной копии
проекта: ваша папка `dist/` и ярлык на рабочем столе не меняются.

### Ручные сценарии

```text
python -m tests.manual.listen_words       # прослушать шесть слов
python -m tests.manual.manual_app_sound   # открыть программу и вызвать звук клавишей P
python -m tests.manual.benchmark_gui      # замерить скорость переключения страниц
```

## Как написан каждый тест

Один тест - одно правило программы. Имя теста - это правило, его можно прочитать как фразу:

```python
def test_weak_words_lesson_does_not_start_without_weak_words(self):
    lesson = self.new_lesson()             # подготовка

    started = lesson.start(WEAK_WORDS)     # действие

    self.assertFalse(started)              # проверка
    self.assertIsNone(lesson.session)
```

Внутри три шага, разделённые пустой строкой (по-английски Arrange - Act - Assert):

1. **подготовка** - создать нужные объекты;
2. **действие** - сделать одно действие, которое проверяем;
3. **проверка** - убедиться, что результат такой, как требуется.

Если упадёт такой тест, по имени сразу понятно, какое правило нарушено.

Ещё несколько правил, которые соблюдаются во всех тестах:

- **Тесты не зависят друг от друга.** Каждый получает свою временную папку, свой
  `user_data/` и, в `gui/`, своё новое окно. Порядок запуска не важен.
- **Случайность предсказуемая.** `use_fixed_random(self)` из `support.py` фиксирует
  генератор случайных чисел на время теста и после теста возвращает его как было.
  Просто вызвать `random.seed()` нельзя: это изменит случайность и для всех следующих тестов.
- **Проверяется поведение, а не внутреннее устройство.** Тест обращается к тому, что видно
  снаружи: результату метода, тексту на экране, файлу настроек. Если переименовать
  внутреннюю переменную класса, тест не должен сломаться. Исключение - `app._on_key`:
  так нажатия клавиш передаются в окно (см. `CLAUDE.md` проекта).
- **Тесты логики работают с маленьким словарём**, написанным прямо в тесте
  (`write_vocabulary` из `support.py`). Так видно, какие слова участвуют, и тест
  не сломается, если в `data/` добавят новые слова. Настоящий словарь проверяет
  отдельный класс `RealDictionaryTests`.
- **Ваши данные не трогаются.** Настоящие `progress.json`, `state.json` и кэш звука
  не используются. Временные папки удаляются после теста, даже если он упал.

## Как работать по TDD

TDD (Test-Driven Development, разработка через тесты) - это порядок работы, а не
только стиль тестов. Тест пишут **раньше** кода, маленькими шагами:

1. **Красный.** Напишите один маленький тест на новое правило. Запустите: он должен
   упасть. Если тест сразу прошёл, он ничего не проверяет, или правило уже есть.
2. **Зелёный.** Напишите самый простой код, при котором тест проходит. Запустите
   все быстрые тесты (`tests/unit`): новый проходит, старые не сломались.
3. **Улучшение (рефакторинг).** Сделайте код понятнее: переименуйте, уберите
   повторы. Тесты после каждого изменения должны оставаться зелёными.

Потом следующее правило, и снова с шага 1.

### Пример из этого проекта: исправление ошибки

С ошибками работают так же: сначала тест, который её показывает.

В "Выборе перевода" иногда повторялись варианты ответа. Сначала появился тест
`test_synonyms_do_not_give_same_option_twice` (`unit/test_vocabulary.py`): словарь
с синонимами "shut down" и "turn off", у которых один перевод "выключить". Тест упал:
это **красный** шаг. Потом в `Vocabulary.distractors` повторы переводов стали убирать
перед выбором, и тест прошёл: **зелёный**. Теперь тест остаётся навсегда и не даст
ошибке вернуться.

Так же исправлена вторая ошибка, обрезанные даты под графиком
(`gui/test_stats.py`, `test_date_labels_fit_inside_chart`).

### Если тест найден, а исправить пока некогда

Тест можно отметить декоратором `@unittest.expectedFailure` ("ожидаемая ошибка").
Тогда он не портит общий результат, но хранит способ воспроизвести ошибку. Когда
ошибку исправят, тест покажет `unexpected success`: значит, декоратор пора удалить.
