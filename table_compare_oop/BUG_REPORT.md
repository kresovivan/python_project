## Итог

Найдено и исправлено **2 бага** в `table_compare/comparator.py`. Оба подтверждены
тестами. Остальные наблюдавшиеся ошибки тестов — артефакты песочницы, а не

## Баг 1 (критический) — «нет данных» становилось `nan` вместо `None`

- **Где:** `table_compare/comparator.py`, оба пути вычисления — базовый `compare()`
  и ускоренный `_compare_unique_keys()`.
- **Суть:** в pandas 3.x при присвоении в столбец DataFrame numpy-массива
  объектного типа, содержащего Python `None`, значение превращается в `NaN`
  (и столбец получает строковый dtype). В результате отсутствующие ячейки
  (`Файл::ключ`, `Файл::поле`) содержали `nan`, а не `None`.
- **Проявление:**
  - нарушен контракт «отсутствие = `None`», на который опирается код и тесты;
  - тест `test_unique_key_comparison_with_unmatched_rows` падал
    (`AssertionError: nan is not None`);
  - в интерфейсе (ttk.Treeview) пропуски отображались бы как строка `nan`.
- **Исправление:** добавлен статический метод `TableComparator._finalize()`,
  который после компоновки колонок приводит столбцы с пропусками к `object`
  dtype с явным `None`. Оба `return` теперь возвращают
  `self._finalize(result, ordered)`.
- **Проверка:** 5/5 логических тестов зелёные, в том числе
  `test_unique_key_comparison_with_unmatched_rows`.

## Баг 2 (критический) — `ValueError: assignment destination is read-only`

- **Где:** `comparator.py`, строки 141 и 154 (`to_numpy(dtype=object)` для
  дополнительных и сравниваемых полей в медленном пути).
- **Суть:** если сравниваемое/дополнительное поле отсутствует в одном из файлов,
  колонка строится из скалярного `None`, и `sa[f].to_numpy(dtype=object)`
  возвращает read-only массив. Следующая строка `arr[pd.isna(arr)] = ''`
  пытается его изменить и падает (в pandas 3.x).
- **Проявление:** исключение при сравнении, если поле есть не во всех файлах
  (достижимо через публичный API `TableComparator.compare`, где отсутствующее
  поле корректно обрабатывается в ускоренном пути, но не в медленном).
- **Исправление:** `to_numpy(dtype=object, copy=True)` в обоих местах.
- **Проверка:** воспроизведение с отсутствующим полем больше не падает.

## Замечания, не являющиеся багами (исправление не требуется)

1. **Ошибки/зависание экспорт-тестов — артефакт песочницы DSH.**
   `test_export_formats` и `test_import_rejects_different_sheet_columns`
   падают из-за запрета записи в `%TEMP%`; `test_large_excel_is_split...`
   зависает, потому что `tempfile.mkstemp` «застревает» во вложенной папке,
   созданной `tempfile.TemporaryDirectory()` (в обычной папке — мгновенно).
   Это ограничения среды запуска, а не дефекты кода. Функциональность
   `ReportExporter` (XLSX, включая разбиение на листы, CSV, HTML, `list_sheets`,
   повторное чтение листов) проверена вручную и работает корректно.

2. **Строка разделителей `csv.Sniffer(... delimiters=';,\t|,')`.** Нестандартная
   запись (порядок, повтор запятой), но функционально эквивалентна `';\t|,'` —
   это множество кандидатов. Не баг.

3. **`load_async` пишет в `self.load_metrics` из рабочих потоков без блокировки.**
   Безопасно под GIL (CPython); косметика.

4. **Коллизия коротких имён.** Два файла с одинаковым именем в разных папках
   дадут совпадающие имена колонок (`Файл::ключ`). Редкий граничный случай.
