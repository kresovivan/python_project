# agent.md — соглашения и правила для агентов в этом репозитории

## Что это за проект

`table_compare_oop` — Tkinter-приложение для построчного сравнения двух и более
выгрузок (CSV / XLSX / XLS) по общему ключу. Выводит совпадения, отличия,
отсутствующие записи; экспортирует результат в CSV / XLSX / HTML.

## Как работаем с кодом

- Код уже объектно-ориентированный. Не переписывайте его «на ООП» без явной
  цели: изменения должны быть точечными и не ломать публичные методы классов
  `TableLoader`, `TableComparator`, `ReportExporter`, `StatisticsAnalyzer`,
  `MainWindow`.
- Инвариант данных: пропуски в результате сравнения — это `None` (не `nan`,
  не `pd.NA`). При добавлении колонок в `compare()`/`_compare_unique_keys()`
  прогоняйте значение через `_finalize()` либо `pd.Series(..., dtype=object)`.
- При чтении в pandas 3.x и последующей записи в массив используйте
  `copy=True` (`to_numpy(dtype=object, copy=True)`).
- Долгие операции — только в фоновых потоках; в GUI — только через
  `self._post(...)`.

## Проверка изменений

```powershell
py -m unittest discover -s tests -v
```

- Логические тесты (`test_*_keys*`, `test_comparison_*`) обязаны проходить.
- Экспорт-тесты зависят от записи во временную папку; если среда её блокирует
  (песочница), сверяйте `ReportExporter` вручную: XLSX обычный и разбитый на
  листы, CSV, HTML, `list_sheets`, повторное чтение листов.

## Стиль

- Сообщения UI и комментарии — на русском.
- Новый код покрывайте тестом в `tests/test_workflow.py`, если меняете логику
  сравнения или экспорта.
- Не меняйте значения в `table_compare/config.py` без обновления всех
  потребителей (`statistics.py`, `exporter.py`, `main_window.py`, тесты).
